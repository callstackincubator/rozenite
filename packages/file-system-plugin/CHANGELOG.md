# @rozenite/file-system-plugin

## 2.5.0

### Minor Changes

- [#541](https://github.com/callstackincubator/rozenite/pull/541) [`56cdf09`](https://github.com/callstackincubator/rozenite/commit/56cdf098c5b3ba2bfc8c4461b1631030c9b40e7d) Thanks [@V3RON](https://github.com/V3RON)! - `list-entries` now pages with the shared agent cursor: pass the
  `page.nextCursor` of one page as `cursor` to get the next, which starts after
  the last entry returned, so files created or deleted while an agent pages are
  never skipped or repeated. `offset` keeps working but is deprecated. The
  result keeps its `entries` key, `total`, `offset` (the index of the first
  entry returned) and `limit`, and gains `page`. `read-text-file` gains
  `offset`, and its result gains `totalBytes`, `truncated` and, when
  truncated, `nextOffset`.
  `list-roots` declares its rows, so agents can project its columns with
  `--fields`.

  Default changes, each reachable through an argument:

  - `list-entries` page size: 100 → 20; `limit` is now capped at 100 (it had
    no cap); default columns: every field → `name,isDirectory,size`
    (`--fields all` brings back the rest). An invalid `limit` (0, negative or
    fractional) is now an error instead of being rounded to a whole number of
    at least 1.
  - `read-text-file` `maxBytes`: 10000000 → 16384. A file within 10 MB is now
    cut to the requested range rather than refused when it is larger than
    `maxBytes`. A file over 10 MB is read when the range reaches past 10 MB:
    `maxBytes` above 10000000 (or `maxBytes: 0`, as before) reads the whole
    file on the device, and an `offset` past 10 MB reads from there. A range
    never ends inside a multi-byte character.
  - `read-image-file`: a base64 data URI → metadata only (`path`,
    `mimeTypeHint`, `size`). `inline: true` returns the data URI, for images
    up to `maxBytes` (default 262144, previously 10000000).
  - `export-file`: no size limit → refuses files over `maxBytes` (default 1048576).

### Patch Changes

- [#560](https://github.com/callstackincubator/rozenite/pull/560) [`a7985fa`](https://github.com/callstackincubator/rozenite/commit/a7985fa7876500ed5dd47bb3e61a97c75e0cfb58) Thanks [@V3RON](https://github.com/V3RON)! - The published packages no longer include development fixtures, tests and build
  configuration (such as `rozenite.config.ts`, `__tests__` and `tsconfig.json`),
  which makes installs smaller: `@rozenite/expo-atlas-plugin` alone drops from
  about 6 MB to 90 KB. Every package now lists its `CHANGELOG.md`, so changelogs
  ship. Plugins generated by `rozenite generate` get the same treatment: they
  publish only their built output, without `rozenite.config.ts`, sources, tests
  or build configuration.

- [#560](https://github.com/callstackincubator/rozenite/pull/560) [`a7985fa`](https://github.com/callstackincubator/rozenite/commit/a7985fa7876500ed5dd47bb3e61a97c75e0cfb58) Thanks [@V3RON](https://github.com/V3RON)! - Fix dev-mode bundles (Re.Pack, webpack, Rspack and Vite) failing to resolve
  `@rozenite/agent-bridge`, `@rozenite/agent-shared` and the other packages
  that publish an `exports` map: it carried a `development` condition pointing at
  TypeScript source that was not in the package. The published packages no
  longer have that condition, so these tools pick the built output in every mode.

  `rozenite build` also stops adding a `development` condition to a plugin's
  `./sdk` export and removes the `./sdk.ts` one that earlier versions wrote; a
  `development` condition you wrote yourself (any other value) is kept. If your
  `package.json` has a `publishConfig.exports`, `rozenite build` now keeps its
  managed entries (`.`, `./sdk`, `./metro`) in step with `exports`.

### Minor Changes

- [#457](https://github.com/callstackincubator/rozenite/pull/457) [`3a29044`](https://github.com/callstackincubator/rozenite/commit/3a29044d0b72354ff80cb2e044afe7d51b800348) Thanks [@V3RON](https://github.com/V3RON)! - Every official plugin now declares the integrations it supports, so a plugin that cannot work in the environment you are debugging can say so instead of loading and failing.

  Controls, Feature Flags, React Hook Form and TanStack Query import nothing from `react-native` on the device and declare every integration, Lynx included. Plugins built on native modules — SQLite, Storage, File System and Performance Monitor — declare React Native only, and so do Network Activity and Require Profiler: `react-native-web` provides no `TurboModuleRegistry` or `DevSettings`, which their device code calls. ### Patch Changes

- [#418](https://github.com/callstackincubator/rozenite/pull/418) [`7d357c3`](https://github.com/callstackincubator/rozenite/commit/7d357c300c8e73751778914a515ca03b5746d1b9) Thanks [@V3RON](https://github.com/V3RON)! - Fix the File System panel showing no roots and no files. The plugin's message channel used `file-system` as its `pluginId`, while every other plugin uses its package name — the id the DevTools runtime derives panels from. Once `@rozenite/shell` started routing `pluginId` messages to only that plugin's panels, every `fs:*` reply from the device was addressed to a plugin id no mounted panel claimed and was dropped, so the panel sat on "No file system roots" forever. The channel now uses `@rozenite/file-system-plugin`, matching the package name and the plugin's agent tools.

  Also stop re-announcing `fs:ready` on every render of the host component. The `useFileSystemDevTools` subscription effect depended on the whole `options` object, which is a new value each render for the usual inline-literal call site; each teardown/re-announce made the panel wipe its roots and entries and refetch them.
